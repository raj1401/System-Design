Queued Spinlocks: MCS Waiting in a 32-bit Linux Lock Word

How Linux compresses fair, local-spinning MCS queues into spinlock_t without bloating every embedded lock

October 3, 2026 · 5 min read

A classic test-and-set spinlock is tiny and fast when idle, but under contention every waiter hammers the same cache line. Ticket locks restore FIFO fairness, yet an unlock still invalidates every waiter’s copy of the lock word. The MCS lock of Mellor-Crummey and Scott fixes that by making each waiter spin on its own node—but a pointer-sized tail plus a node is too large for the thousands of spinlock_t instances embedded across the Linux kernel. Queued spinlocks (qspinlocks) keep the MCS idea while packing the entire public lock into a single 32-bit word: a locked byte, a pending bit, and a compressed tail of CPU number plus nesting index, with the real MCS nodes living in a per-CPU array.

Why naive spinning hurts

In a test-and-set (or test-and-test-and-set) lock, every contending CPU repeatedly loads or CAS-es the same word. On a coherent interconnect that means the lock’s cache line bounces among cores on every failed attempt and again on unlock. Ticket locks serialize acquisition order with a next/owner counter pair, but waiters still observe the shared owner field, so unlock traffic scales with the number of spinners. On large machines that coherence tax dominates short critical sections in the VFS, page cache, and scheduler paths.

Design constraint. Linux assumes spinlock_t fits in four bytes and is embedded in structures that cannot grow (historically including struct page). Any MCS-style redesign had to preserve that size and the existing spin_lock / spin_unlock API.

MCS: local spinning via a queue of nodes

An MCS lock stores a tail pointer. Each waiter provides an mcs_spinlock node with a next pointer and a locked flag. Acquire does an atomic exchange of the tail with the address of the waiter’s node. If the previous tail was null, the lock is free. Otherwise the waiter links itself behind the predecessor and spins on its own node->locked. Unlock either clears the tail (no successor) or stores into the successor’s locked field—exactly one cache-line transfer to hand off, independent of queue length. Fairness is FIFO by construction.

The catch: classic MCS needs a pointer-sized lock word plus a node that must travel from lock to unlock (or be looked up). That footprint and API change made a straight MCS replacement unsuitable for every kernel spinlock.

The 32-bit qspinlock word

Linux’s answer, merged around the 3.15 era from work by Waiman Long and Peter Zijlstra, keeps queue state off the lock object. Each CPU owns four MCS nodes—one each for task, softirq, hardirq, and NMI nesting. The public lock is only a u32 (see include/asm-generic/qspinlock_types.h):

  • Bits 0–7 — locked byte (full byte so unlock is a single store-release of zero)
  • Bits 8–15 — pending byte (one bit used; full byte for cheap 16-bit ops when NR_CPUS < 16K)
  • Bits 16–17 — tail nesting index (0..3 into the per-CPU node array)
  • Bits 18–31 — tail CPU number encoded as cpu + 1 so zero means “no queue”

Three paths to ownership

Fast path

queued_spin_lock in asm-generic/qspinlock.h tries a single acquire CAS of the lock word from 0 to _Q_LOCKED_VAL. That is the uncontended case—and the common case. Unlock is deliberately a byte store-release of zero to lock->locked, cheaper than the read-modify-write ticket unlock required.

Pending optimization

If the lock is held but no one else is waiting, the slowpath sets the pending bit instead of joining an MCS queue. That lone waiter spins on the locked byte of the lock word. When the owner releases, the pending waiter clears pending and sets locked in one transition (clear_pending_set_locked). A second contender seeing pending (or any non-locked bits) falls through to the full queue. This avoids touching a (possibly cold) per-CPU MCS node for the common “exactly one waiter” pattern.

Slow path: MCS queue

queued_spin_lock_slowpath claims a nesting slot via node->count, encodes tail = (cpu+1) | idx, and xchg_tails it into the lock word. If a previous tail existed, it publishes prev->next = node and spins on node->locked until promoted to queue head. The head then waits until both locked and pending are clear, claims the lock (clearing the tail if it is still the sole waiter, otherwise only setting locked), and unlocks its successor by writing next->locked. Nested IRQ/NMI acquisitions use additional slots in the same per-CPU array of four nodes.

Test-and-set / ticket

  • All waiters observe one shared word
  • Unlock coherence traffic grows with N waiters
  • Ticket is fair; TAS is not
  • Fits in 32 bits; simple unlock
  • Scales poorly on large SMP

MCS / qspinlock

  • Waiters spin on private nodes (local cache lines)
  • Handoff is O(1) remote write to successor
  • FIFO fairness preserved
  • qspinlock: 32-bit word + per-CPU nodes
  • Pending path skips queue for one waiter

Fairness and where it shows up

Like ticket locks, qspinlocks hand off in arrival order once waiters are queued, so a core cannot indefinitely steal under heavy contention the way unfair TAS can. Versus tickets, the big win is scalability: queue members do not bounce the lock word until they reach the head (or take the pending shortcut). Architectures that select qspinlock remap arch_spin_* to the queued helpers, so spin_lock across x86, arm64, and other supported arches is qspinlock underneath—protecting softirq lists, runqueues, inode/page locks, and countless short critical sections that must not sleep.

Real-world use cases

arch_spinlock_t
Default architecture spinlock on x86, arm64, and other qspinlock adopters; every spin_lock() goes through this word.
IRQ / softirq nesting
Four per-CPU MCS nodes keep task, softirq, hardirq, and NMI acquisitions from sharing one waiter node.
Hot VFS / FS paths
LWN’s original AIM7 numbers showed large gains on contended filesystem workloads where ticket unlock bounced many waiters.
Paravirt spinlocks
PV qspinlock variants add kick/wait hooks so overcommitted guests can halt instead of burning host cycles while queued.

qspinlock is not a cure for lock contention—long hold times still serialize work. It is an optimization of the waiting protocol so that when many cores do collide, coherence traffic stays bounded and the lock object itself stays four bytes.
