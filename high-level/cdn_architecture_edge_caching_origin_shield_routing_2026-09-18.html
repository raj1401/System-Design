CDN Architecture: Edge Caching, Origin Shield & Request Routing

Moving bytes closer to users — and keeping origin servers from melting under global demand

September 18, 2026 · 5 min read

The Concept, Briefly

A Content Delivery Network (CDN) is a geographically distributed reverse-proxy cache that sits between clients and your origin. Users are steered to a nearby Point of Presence (PoP); the edge serves cache hits in single-digit to tens of milliseconds, and only misses travel onward through mid-tier caches or an origin shield before reaching the authoritative source.

Architecturally, a CDN splits into a data plane (edge selection, TLS termination, cache lookup, origin fetch, response delivery) and a control plane (config distribution, routing policy, certificate management, purge fan-out, monitoring). The design trades three tensions: freshness vs. latency (TTL), granularity vs. hit ratio (cache keys), and origin protection vs. operational complexity (tiered caches and shields).

Why this matters: A well-tuned CDN routinely absorbs 90–99% of cacheable traffic at the edge, collapses stampedes via request coalescing, and survives origin outages with stale-if-error. Without shields and careful cache-key design, a viral asset or global purge can turn every PoP into a synchronized DDoS against your origin.

Underlying Ideas & Mechanisms

Request Routing: Anycast vs DNS GSLB

Before a byte is cached, the client must land on a PoP. Two dominant mechanisms exist.

Anycast announces the same IP prefix from many PoPs via BGP. Routers deliver packets to the topologically nearest announcement. Failover is BGP convergence (often seconds), independent of DNS TTLs. Cloudflare’s HTTP network is anycast end-to-end; when a PoP fails, the route is withdrawn and traffic shifts without waiting for resolvers to expire records.

DNS-based GSLB (used historically by Akamai and CloudFront) returns different A/AAAA records based on the recursive resolver’s location (or EDNS Client Subnet). It allows fine-grained geo-steering and compliance routing, but failover is gated by DNS TTLs (typically 30–60s), and resolver location is not always the user’s location (corporate NATs, public resolvers).

Inside a PoP, a Layer-4 load balancer must pin each TCP/QUIC flow to one cache server. Google’s Maglev (NSDI ’16) computes a consistent-hash lookup table from the backend set and selects by 5-tuple hash — no shared connection state across LB machines, and removing one of N backends remaps roughly 1/N of flows.

CDN Request Path: Edge → Shield → Origin

HTTP Caching Semantics (RFC 9111)

CDN edge caches are shared caches in the sense of RFC 9111. Freshness lifetime is computed in priority order: s-maxage (shared-cache override) → max-age → Expires → heuristic (often ~10% of Last-Modified age). A typical layered directive:

Cache-Control: max-age=60, s-maxage=3600, stale-while-revalidate=86400

Browsers revalidate often; the CDN holds the object for an hour; RFC 5861 extensions (stale-while-revalidate, stale-if-error) let the edge serve slightly stale content while refreshing or when origin returns 5xx — Informational extensions that caches may ignore, but every major CDN implements them.

The cache key defaults to method + host + path + query. Over-varying (e.g. Vary: User-Agent) fragments the cache into near-zero hit ratio. Best practice: normalize tracking query params out of the key, vary only on meaningful dimensions (Accept-Encoding), and strip signed-URL signature parameters so many users share one cached object.

Origin Shielding, Tiered Cache & Request Collapsing

Without a mid-tier, each edge PoP independently fetches the origin on miss. A viral asset across 100 PoPs means 100 concurrent origin pulls. An origin shield (or regional/upper-tier cache) consolidates those misses: edges fetch the shield; the shield collapses concurrent identical misses into a single origin request.

Cloudflare’s Smart Shield / Tiered Cache organizes data centers into lower-tier (user-facing) and upper-tier groups so only upper tiers contact origin; Cache Reserve adds persistent R2-backed storage as an ultimate upper tier for long-tail assets that would otherwise churn out of RAM. Request collapsing (also called coalescing) is the stampede brake: many waiters, one fetch.

Anycast Landing + Maglev Inside the PoP

Invalidation: Versioned URLs, Soft Purge, Surrogate Keys

Hard purge deletes immediately and can create a thundering herd. Soft purge marks stale and revalidates on the next request — safer for routine updates. Fingerprinted static assets (main.a1b2c3d4.js) make invalidation a non-problem: new content is a new URL with year-long TTLs.

For CMS and commerce sites, surrogate keys (Fastly Surrogate-Key, Cloudflare Cache-Tag) tag objects by product/category so one purge call invalidates a logical group. These headers descend from the W3C Edge Architecture Note (2001), not an IETF RFC — treat them as a vendor-stable edge contract.

Prefer for static & media

  • Versioned / content-addressable URLs
  • Long s-maxage (days–year)
  • Pre-compressed Brotli at build time
  • Origin shield for launch stampedes
  • Manifest TTL ≪ segment TTL for HLS/DASH

Prefer for HTML & APIs

  • Short s-maxage + stale-while-revalidate
  • Soft purge over hard purge
  • Surrogate keys / cache tags for groups
  • Normalize cache keys aggressively
  • stale-if-error for origin outages

Real-World Use Cases

Netflix Open Connect
ISP-embedded appliances pre-position content-addressable video encodes; control plane in cloud, data plane inside ISP networks — push model with near-infinite TTLs.
Cloudflare Anycast + Tiered Cache
Hundreds of cities announce the same VIP; Smart Tiered Cache and Cache Reserve collapse misses and keep long-tail objects off origin.
Amazon CloudFront
DNS/GSLB edge selection with Regional Edge Caches and optional Origin Shield so regional misses converge before hitting S3 or custom origins.
Fastly Soft Purge
Powderhorn gossip fan-out marks objects stale fleet-wide in ~150 ms median; soft purge avoids origin stampedes on routine CMS updates.
E-commerce product pages
Surrogate keys tag product, category, and campaign; a price change purges every page showing that SKU without enumerating URLs.
Signed media URLs
Origin signs short-lived policies; edge verifies before cache lookup — strip signature params from the cache key so hits stay shared.

Trade-offs to Keep in Mind

Long TTLs raise hit ratio but widen staleness; short TTLs keep content fresh but reintroduce origin load. Over-specific cache keys destroy CHR; under-specific keys risk serving the wrong personalized response. Shields protect origin but add a hop and a failure domain — plan multi-shield or regional upper tiers. Anycast failover is fast, but BGP flaps can reset long-lived TCP/QUIC sessions; sticky media may still want careful PoP affinity.

Start with anycast or managed DNS routing, normalize cache keys, layer s-maxage with stale-while-revalidate, enable request collapsing and an origin shield before your first viral launch, and use versioned URLs for everything that can be fingerprinted.
